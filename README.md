# 자리 배치 (Seat Randomizer)

초등 교실용 설치 가능한 정적 웹앱. 4행 × 6열, 두 책상씩 3분단을 유지하고 이름만 섞습니다. 8개 학급, 최대 24명, 저장·복원, 전체화면, A4 가로 인쇄, 오프라인 앱 실행을 제공합니다.

## 빠른 실행

Node 22 이상으로 `npm test`를 실행합니다. 앱 실행에는 빌드나 npm 설치가 필요 없습니다.

```sh
python3 -m http.server 8080
```

브라우저에서 http://localhost:8080/seat/ 를 여세요. 연결 설정 → 체험 모드로 가상 학생 10명을 확인할 수 있습니다. 체험 배치는 저장하지 않습니다. 일반 파일 더블클릭(file://)으로는 PWA와 모듈이 작동하지 않습니다.

## 비공개 Google Sheet 연결

1. 비공개 스프레드시트 하나를 만들고 탭 이름을 `3-1`, `3-2`, `4-1`, `4-2`, `5-1`, `5-2`, `6-1`, `6-2`로 지정합니다.
2. 각 탭 A1에 `이름`, A2부터 이름을 한 행에 하나씩 입력합니다. 빈 행은 제외하며 25명 이상은 오류로 처리합니다. 동명이인은 각각 별도 학생으로 유지됩니다.
3. 공유 설정은 **제한됨**으로 유지합니다. 실제 사용할 교사 계정에만 뷰어 권한을 부여합니다. 웹에 게시하지 않습니다.
4. Google Cloud 프로젝트에서 Google Sheets API를 사용 설정합니다.
5. Google Auth Platform에서 앱 이름·지원 이메일·동의 화면·대상을 설정합니다. 학교 조직 내부 앱이 가능하다면 내부 대상 사용을 검토합니다. 외부 테스트 앱이면 실제 교사 계정을 테스트 사용자에 추가합니다. 조직 정책에 따라 관리자의 승인이 필요할 수 있습니다.
6. OAuth 클라이언트 유형을 **웹 애플리케이션**으로 생성합니다. 승인된 JavaScript 원본에 `http://localhost:8080`, 실제 Pages 원본 및 실제 사용자 도메인 원본을 등록합니다. 원본에는 `/seat` 경로를 넣지 않습니다. 한글 도메인은 브라우저의 실제 ASCII/Punycode 원본과 일치시키세요.
7. 앱 연결 설정에 클라이언트 ID와 스프레드시트 ID만 입력합니다. 시트 ID는 URL의 `/d/`와 `/edit` 사이 값입니다. 클라이언트 Secret·비밀번호·토큰은 입력하지 않습니다.
8. Google 로그인 버튼으로 읽기 권한을 승인합니다. 이후 학급 선택 또는 최신 명단 버튼으로 최신 값을 읽습니다. 만료 후에는 로그인 버튼을 다시 누릅니다. 페이지 새로고침 후에도 다시 인증합니다.

인증 방식은 Google Identity Services의 OAuth token model입니다. 토큰은 JavaScript 메모리에만 보관하고 localStorage·Service Worker·로그·URL에 기록하지 않습니다. Google Sheets가 계정의 시트 접근 권한을 실제로 검사합니다. 클라이언트 ID·시트 ID를 숨기는 방식은 보안 수단이 아닙니다. 별도 백엔드와 API Key는 사용하지 않습니다.

**권한 범위:** `spreadsheets.readonly`는 사용자에게 접근 가능한 모든 Google 스프레드시트의 읽기 권한이며, 특정 탭이나 이 파일에만 제한되는 OAuth 범위가 아닙니다. 앱은 설정한 한 파일의 A열만 요청합니다. 이 범위는 민감 범위이므로 외부 공개 운영에는 Google 검증 요구사항을 확인해야 합니다. 전용 교사 계정에 필요한 시트만 공유하면 계정의 접근 범위를 줄일 수 있습니다. 파일 단위 OAuth가 꼭 필요하면 향후 Google Picker + `drive.file` 설계가 필요합니다(이 버전에는 포함되지 않습니다).

공식 자료:
- https://developers.google.com/identity/oauth2/web/guides/use-token-model
- https://developers.google.com/workspace/sheets/api/scopes
- https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get

## 저장·복원 및 개인정보

- 학생 실명 TXT/JSON/CSV, 시트 내보내기, API Secret, 계정 비밀번호, 액세스 토큰을 GitHub에 올리지 마세요. `.gitignore`는 보조 수단이므로 커밋 내용을 직접 확인하세요.
- 정적 Service Worker 캐시는 정확히 지정된 동일 출처 앱 리소스만 저장합니다. Google API·인증 요청·명단·쿼리 URL은 캐시하지 않습니다.
- 기본 상태에서 명단은 메모리에만 있습니다. 오프라인 명단 저장은 연결 설정에서 **명시적으로 선택**할 때만 사용합니다.
- '현재 배치 저장'을 누르면 이름을 포함한 배치가 해당 기기의 localStorage에 저장됩니다. 배치는 학급별로 저장하고 원본 명단과 별도 키를 사용합니다. 만료 기간은 7일이며 앱 실행 시 만료 항목을 삭제합니다. 앱을 열지 않는 동안 브라우저가 자동 삭제하는 것은 아닙니다.
- 저장 데이터는 암호화되지 않으며 기기의 사용자와 같은 원본의 스크립트가 읽을 수 있습니다. 다른 앱과 `/seat`를 같은 원본에 호스팅하면 localStorage가 공유되므로 신뢰할 수 있는 코드만 호스팅하세요. 공용 전자칠판에서는 저장을 사용하지 않는 편이 적합합니다.
- 기기 데이터 삭제 버튼은 전체 학급의 명단과 배치를 삭제하고 메모리 토큰을 제거합니다. Google 권한 철회는 온라인에서 수행되며 실패할 경우 Google 계정의 연결된 앱 관리에서 별도로 철회하세요. 공개 클라이언트 ID·시트 ID 설정은 남습니다.
- 현재 명단과 저장 명단의 이름 구성(중복 포함)이 달라지면 이전 배치 복원을 차단합니다. 개인정보의 별도 수집 서버·분석 서비스·로그는 없습니다.

## PWA·오프라인

`seat/manifest.json`의 start_url·scope·id는 `./`이며 Service Worker도 `seat/` 안에서만 동작합니다. 앱 파일과 아이콘은 상대 경로입니다. HTTPS 또는 localhost에서 동작합니다. 최초 온라인 접속이 성공한 뒤 정적 앱이 오프라인에서 실행됩니다. Google 로그인은 오프라인에서 불가능합니다. 오프라인 사용을 선택해 저장한 명단 또는 현재 메모리 명단으로 셔플할 수 있습니다. 오프라인 선택을 켠 경우 저장 배치만으로도 복원할 수 있습니다.

Chrome/Edge: 설치 버튼이 표시되면 클릭하거나 브라우저 메뉴의 앱 설치를 사용합니다. iPad/iPhone: Safari 공유 메뉴 → 홈 화면에 추가를 사용합니다. 브라우저별 설치 UI 및 정책은 다를 수 있습니다. 자동 설치를 강제하지 않습니다. 업데이트 시 `sw.js`의 CACHE 버전을 올리고 설치된 앱의 창을 모두 닫은 뒤 다시 열면 새 정적 캐시가 적용됩니다.

## GitHub Pages 배포

제공 파일은 **도메인 루트 아래 여러 도구를 두는 저장소 구조**입니다.

```text
/
  index.html
  seat/             # 실제 앱
  .github/workflows/pages.yml
  tests/
  README.md
```

1. 실제 사용할 GitHub 저장소를 생성하거나 기존 교사용 도구 저장소에 병합합니다. 파일 업로드 시 숨김 폴더 `.github`도 포함하세요.
2. 기본 브랜치를 `main`으로 맞춥니다. Pages의 Source를 **GitHub Actions**로 선택합니다.
3. 워크플로는 테스트 후 index.html과 seat/만 배포합니다. README·테스트·설정 안내는 사이트 산출물에 포함하지 않습니다.
4. 사용자 사이트 저장소 `<사용자명>.github.io`에서는 `https://<사용자명>.github.io/seat/`가 됩니다. 일반 프로젝트 저장소에서는 `https://<사용자명>.github.io/<저장소명>/seat/`가 됩니다. 상대 경로로 둘 다 동작합니다.
5. 별도 저장소 이름을 `seat`로 쓰고 사용자 사이트 도메인을 상속하려면 **seat/ 안의 앱 파일을 해당 저장소 루트로 이동**해야 `/seat/`가 됩니다. 현재 구조를 그대로 올리면 `/seat/seat/`가 됩니다. 이 경우 워크플로의 배포 복사 경로도 조정하세요.

## 커스텀 도메인과 /seat

이 패키지는 실제 등록 도메인이나 DNS를 변경하지 않았습니다. 실제 소유 도메인·현재 호스팅·저장소를 확인한 후 설정하세요.

권장: 사용자 사이트 또는 루트 사이트 저장소에 이 구조를 배포하고 GitHub Pages Settings의 Custom domain에 소유 도메인을 지정합니다. GitHub 공식 DNS 안내에 따라 소유권 확인 및 A/AAAA/ALIAS 또는 CNAME을 설정하고 HTTPS를 활성화합니다. GitHub Actions 배포에서는 Settings의 Custom domain 설정을 사용하세요. 그러면 `https://실제도메인/seat/`가 앱 경로입니다. `/seat`는 디렉터리 경로 `/seat/`로 정규화될 수 있습니다.

DNS는 `/seat` 같은 경로만 따로 다른 서버에 연결할 수 없습니다. 기존 도메인 루트가 다른 서비스에 연결되어 있다면 해당 호스팅의 경로 라우팅/프록시 또는 전체 루트 이전을 검토해야 합니다. 현재 루트 서비스를 확인하지 않고 DNS를 변경하지 마세요. 추후 timer/, random/, english/를 추가하고 배포 워크플로에 해당 폴더를 포함할 수 있습니다.

공식 자료: https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/about-custom-domains-and-github-pages
